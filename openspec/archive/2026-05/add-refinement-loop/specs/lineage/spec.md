# Spec — lineage.yml

## Per-skill index

```yaml
slug: kubernetes-pvc-resize
current_version: 3
iterations:
  - version: 1
    kind: imported
    created: 2026-05-24
    judge_score: 0.62
    status: superseded
  - version: 2
    kind: refined
    created: 2026-05-26
    judge_score: 0.78
    status: superseded
  - version: 3
    kind: refined
    created: 2026-05-27
    judge_score: 0.91
    status: current
  - version: 4
    kind: refined
    created: 2026-05-27
    judge_score: 0.73
    status: rejected
    reject_reason: "lost the gotcha about UPDATE-heavy tables"
```

## Status semantics

| status | Meaning |
|---|---|
| `current` | This is the iteration `SKILL.md` mirrors. Exactly one per lineage. |
| `superseded` | Was current; replaced by a later accepted iteration. |
| `pending` | Generated by `refine`, awaiting accept/reject. |
| `rejected` | Explicitly rejected via `refine-reject`. File stays on disk. |
| `accepted` | Synonym for `current` — but `current` is the canonical marker. We use `accepted` only as an `Iteration.kind` (to record that the user explicitly promoted v{N-1} to be current). |

## API

```python
class Iteration(BaseModel):
    version: int
    kind: Literal["imported", "extracted", "refined", "accepted"]
    created: date
    judge_score: float | None = None
    status: Literal["current", "superseded", "pending", "rejected"]
    reject_reason: str | None = None      # required iff status == "rejected"

class Lineage(BaseModel):
    slug: str
    current_version: int
    iterations: list[Iteration]
```

`Lineage` enforces exactly one `current` status across `iterations`,
that `current_version` matches that iteration's `version`, and that
versions are strictly monotonic starting at 1.

## Storage

```python
def read_lineage(root: Path, slug: str, *, draft: bool) -> Lineage: ...
def write_lineage(root: Path, slug: str, lineage: Lineage, *, draft: bool) -> Path: ...
```

YAML serialization uses `sort_keys=True` for stability (same as
SKILL.md frontmatter).

## Verification

`forge lineage verify <slug>` cross-checks lineage.yml against the
filesystem:

- Every iteration listed in `lineage.iterations` has a matching file
  under `iterations/`.
- Every file under `iterations/` is listed in `lineage.iterations`.
- The `current_version` file content matches `SKILL.md` byte-for-byte.

Called automatically before `refine-accept` and `refine-reject` so a
corrupted lineage doesn't silently propagate.

## Out of scope

- Cross-skill lineage (forks).
- Encrypted lineage. The audit trail is plaintext.
